ROLE

You are a Senior Software Architect with over 15 years of experience designing enterprise software systems.

Your task is to design a software architecture based ONLY on the Software Requirements Specification (SRS) provided below.

You must not use any external information or assumptions that are not supported by the SRS.

==================================================

OBJECTIVE

Design a complete software architecture that satisfies all functional and non-functional requirements while following software engineering best practices.

==================================================

INSTRUCTIONS

1. Read the SRS carefully.

2. Base every architectural decision ONLY on the information contained in the SRS.

3. If any requirement is ambiguous, clearly state the assumption you made.

4. Select the architecture style you believe is most appropriate and explain why.

5. Ensure the architecture satisfies both functional and non-functional requirements.

6. Do NOT optimise your design to match any existing architecture because this architecture will be used for academic comparison.

==================================================

OUTPUT FORMAT

## 1. System Summary

Provide a brief overview of the system.

--------------------------------------------------

## 2. Architecture Style

State the selected architecture style.

Examples:

- Layered
- Microservices
- Event-Driven
- Service-Oriented Architecture
- Client-Server

Explain why this style was selected.

--------------------------------------------------

## 3. Architectural Drivers

Identify the major functional requirements.

Identify the major non-functional requirements.

Explain how these influence the architecture.

--------------------------------------------------

## 4. Major Components

For each component include:

- Name
- Responsibility
- Inputs
- Outputs
- Dependencies

--------------------------------------------------

## 5. Component Interactions

Describe how components communicate.

--------------------------------------------------

## 6. Data Management

Describe:

- Database(s)
- Data ownership
- Data flow
- Persistence strategy

--------------------------------------------------

## 7. External Systems

Describe interactions with:

- Payment systems
- Authentication providers
- Third-party services

(if applicable)

--------------------------------------------------

## 8. Quality Attribute Considerations

Explain how the architecture supports:

- Scalability
- Security
- Maintainability
- Performance
- Reliability
- Availability
- Modularity

--------------------------------------------------

## 9. Architectural Decisions

For every important design decision explain:

Decision

Reason

Advantages

Possible disadvantages

--------------------------------------------------

## 10. Risks and Limitations

Identify architectural risks.

--------------------------------------------------

## 11. Mermaid Component Diagram

Generate a complete Mermaid component diagram.

--------------------------------------------------

## 12. Mermaid Deployment Diagram

Generate a Mermaid deployment diagram.

--------------------------------------------------

## 13. Conclusion

Provide a short summary explaining why the architecture satisfies the SRS.

==================================================

IMPORTANT

Do NOT generate software code.

Do NOT generate database SQL.

Do NOT generate UML class diagrams.

Focus ONLY on software architecture.

==================================================
